#### 2. 同時実行制御（楽観的ロック） ⚠️
**現状**:
- ポイント消費時にversion番号やタイムスタンプによるロックなし
- 二重消費の可能性あり

**必要な実装**:
```python
# services/v2/points_service.py に追加
async def use_points_with_lock(self, user_id: str, amount: int):
    # version番号でロック
    current = await self.get_points_with_version(user_id)
    if current["points"] < amount:
        raise InsufficientPointsError()
    
    # version確認しながら更新
    result = supabase.table("v2_user_points")\
        .update({"current_points": current["points"] - amount,
                 "version": current["version"] + 1})\
        .eq("user_id", user_id)\
        .eq("version", current["version"])\  # ここがポイント
        .execute()
```

**影響**: 高負荷時にポイント不整合の可能性

## ⚠️ リスク評価

### 高リスク項目
1. **コラム消費未実装**: ユーザー混乱の可能性
2. **同時実行制御なし**: ポイント不整合リスク
3. **購入機能なし**: ポイント枯渇時の離脱

### 対策案
1. コラム機能を一時的に無効化
2. 運用初期は監視強化
3. 初期ボーナスを多めに設定
